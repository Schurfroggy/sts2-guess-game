# 尖塔猜牌与图鉴

《杀戮尖塔 2》本地卡牌数据库和浏览器图鉴。当前快照来自游戏公开测试版 `v0.113.1`（`d09d48e5`），按 `ModelDb.AllCards` 收录 717 张注册卡牌，包括测试角色、衍生牌、状态牌和退役占位牌。这不是所有卡都能随机获取的清单。

## 好友房猜牌规则

**一局**指从发牌到结算；**回合**指轮到某一位玩家猜牌，直到猜对、用完次数或主动结束回合。提问、回答和交谈在线下或语音通话中进行，网页不提供聊天，也不限制提问次数。

### 首页、昵称与进房

- 首页可编辑昵称并选择头像，不需要注册、密码或正式账号。昵称、头像偏好和随机生成的临时身份凭证保存在当前浏览器的站点数据中；昵称不是身份凭证，清除站点数据后不能仅凭原昵称取回原座位。
- 输入 **4 位数字 PIN** 加入房间，保留前导零（如 `0123`）。PIN 对应的房间不存在时，由第一位进入的人创建，并成为房主。不做公开大厅或房间列表。
- 首页右上角和房间左上角提供图鉴入口。开局前和结算后可以查看图鉴，浏览图鉴期间保留房间身份与座位，并继续同步房间状态。房主开局时照常发牌，图鉴检测到开局后自动回到原房间。房间内点卡名会打开游戏用卡面。

### 房间、房主与猜牌范围

- 玩家按人数围桌排列，座位显示玩家选的头像和昵称。开局前没有卡名或卡面；房主可将权限转移给房内另一名参与玩家。
- 非游戏进行中，房主可以多选卡池（新房间默认不选「衍生」和「愚者」，其余全选，至少保留一个）、设置每回合可猜 1–5 次（默认 1 次），以及开启关键词联想或消耗整回合查看图鉴（两者默认关闭）。不按类型、费用或稀有度限制，也不支持单独禁用某张牌。
- 开局至少需要两名在线玩家，未使用的牌须足够给每名在线参赛者发一张。离线成员保留房间身份，重连后可观战，并在下一局开局时重新参赛。候选来自游戏图鉴可见的卡牌。本局发牌与投票补牌使用同一份范围。房间最多八人（含观战）。

### 发牌、卡面与观战

- 每局开始时，系统从候选牌池给每位参赛玩家随机发一张牌。玩家不能自行换牌，刷新或重连也不能重新抽牌。
- 局内未猜出的玩家可以看别人的牌，不能看自己的牌。可见的卡名以可点击的小标签显示在昵称旁；点击后弹出纯卡面预览，不显示图鉴的属性表或源码信息。卡面下方可勾选「查看升级」，仅切换预览，不改变实际牌或答案。
- 已猜出的玩家和观战者都能看到所有卡名和卡面。新玩家中途加入先观战，不发牌、不占本局回合、不参与投票换牌；仍留在房内的观战者在下一局发牌时入座。
- 服务端按接收者身份发送房间状态：未猜出玩家自己的卡牌 ID、名称和数据不发送给该玩家，不能只在页面上隐藏。猜测由服务端判定。

### 回合、判猜与结算

- **每次整局重新发牌，只随机选一次先手。** 此后固定按座位逆时针轮转，绕回桌首也不再随机；跳过已猜出的玩家。当前玩家的头像用黄色高亮。
- 只有当前玩家能点桌面中央的「猜测」并提交。输入必须与自己的卡牌简体中文名完全一致，不接受简称、错字或其他写法。猜对立即结束回合并标记为「已猜出」；猜错不公布答案，仍有次数可继续猜，用完则轮到下一位。每位玩家的新回合重新获得全部次数。
- 当前玩家可点「猜测」右边的「跳过」，放弃剩余猜测次数并直接轮到下一位。若房主允许查看图鉴，本回合还没提交过猜测时，可以点「跳过」右边的「查看图鉴」，消耗本回合的全部猜测次数并交棒给下一位。座位和牌不变；再轮到自己时，图鉴自动返回房间。
- 开启关键词联想后，猜测框按简中卡名的开头匹配所选卡池，最多显示 5 个不同卡名。匹配包含已用过的牌。点击提示会填入卡名，玩家仍需点击「提交猜测」。
- **只剩一名玩家没猜出时自动结算**，房主也可以提前强制结束。结算后在所有参赛座位旁公开卡名，包括自己的牌，点击卡名可看卡面，不自动展开大图。
- 房主可在右上角点击「结束本局」，确认后只结算，不自动发牌。结算后可修改设置，或另点「开始下一局」。新局清空猜测状态和票数，并重新随机选先手。
- 局内参赛玩家可点桌面下方右侧的对话气泡，选择一句原版角色或奶龙的台词发送。服务端在本局保留最近 30 秒的发言，短时同步延迟后可补收。气泡从收到台词时起显示约 2 秒，同一玩家的新台词会替换上一条。每位发送者间隔至少一秒，发言不影响回合或猜测次数。原版角色台词来自游戏资源包 `localization/zhs/characters.json` 的 `.banter.alive.endTurnPing`。
- 猜牌桌正下方的圆形「√」「×」可直接发送勾叉气泡，显示在发送者头像旁，与快捷发言共用同步、淡出和发送间隔。
- 点击其他座位的头像可以送鲜花或扔鸡蛋；长按道具可连发，点小窗外收起。道具会从发送者飞向目标，鸡蛋命中后溅开；音效在浏览器允许播放后生效。连发分批同步并限速，不影响牌面、评分或回合。

### 房间记忆池

- 记忆池跨局保留。开局发牌和投票补牌都只抽未用牌；发出即记入，不论是否猜对，换下也不退回。「打击」「防御」各算一组，抽到时从已选卡池内随机选一个版本，此后所有同名版本都不能再抽，直到记忆池重置。其他牌仍按卡牌 ID 独立计算。
- 按房主选中的卡池计算消耗比例，显示在房间号右侧。开局整批发牌或投票补牌后达到或超过 70%，立即结算并锁住下一局。房主可点击「清空记忆池」解除锁定，再手动开始下一局。
- 只允许在非游戏进行中清空记忆池。保存设置变更（卡池、猜测次数、关键词联想或对局查看图鉴）也会自动清空；保存原设置不会清空。

### 投票换牌

- 参赛玩家打开别人尚未猜出的卡面后，可点弹窗右下角的「投票换牌」。不能投自己的牌，也不能对已猜出的玩家发起投票。
- 同一张牌每人最多一票。**除持牌人外，本局所有其他参赛玩家一致同意**才更换；已猜出的参赛玩家也能投票，观战者不计入。弹窗显示已投票数和所需票数。
- 通过后为该座位抽一张未用牌，清空该牌票数，不重置本回合剩余猜测次数。除非触发记忆池结算，持牌人仍看不到新牌，当前回合和座位顺序不变。
- 猜测期间换牌会提示持牌人重新猜测，针对旧牌提交的答案不扣次数。

### 卡牌「考」评分

- 对局中和结算后，打开可见的卡面即可点「考」加 1 分，再点「已考」撤回自己的 1 分。局内猜出自己的牌后可给它评分，结算后未猜出的玩家也可给自己的牌评分。同一浏览器身份对同一张卡在所有房间和对局中最多贡献 1 分；「考」不改变回合、抽牌或投票换牌。
- 房间卡面下方的评分栏显示「考排名」和「分值」，右侧是「考」按钮。图鉴以只读方式显示这两项。在库卡牌按分值从高到低排，同分按卡牌稳定键排序。正分第 1–25 名为金色、26–50 名为银色、51–100 名为铜色，其他显示灰紫色「100+」。加分和撤回后同步更新，不改变图鉴列表的默认排序。
- 房间和图鉴的牌名右边显示「社区」标签、社区分和渐变艺术字徽记。48–100 金色 S，33–47 紫色 A，21–32 蓝色 B，1–20 青绿色 C，无样本显示「无数据」及灰色 F。图鉴还显示原始抓取率和选中/出现次数。社区分不计入玩家手动点的「考」，也不改变图鉴的默认排序。

### 刷新与断线恢复

- 同一浏览器刷新或短暂断网后，在房间仍存在且临时身份凭证有效时，自动恢复到原房间和原座位（或观战位），不视为新加入。
- 同一浏览器的另一标签页换房时，旧房间的操作弹窗会关闭，发往原房间的旧请求无法改变新房间。
- 由服务端保留本局状态；重连恢复原有房主权限、卡牌、投票和已猜出状态，并同步当前回合。短暂离线不重新发牌、不改变座位顺序，也不把离线玩家从投票人数中扣除。
- 清除站点数据或换浏览器后，没有原凭证就只能以新身份进房。房间状态保存在服务端内存，重启服务或整个房间连续 5 分钟无人访问会清空。暂时离线不会自动换房主；房主在结算后主动离房时，权限交给最早进入的剩余玩家。

## 打开网站

安装 Node.js 22.13 或更新版本。从源码仓库克隆后，先按「重建」生成卡牌数据和卡面素材，再运行 `npm run dev`。打开 [首页](http://127.0.0.1:4173/)，右上角可进入图鉴。生成数据后，运行无需安装 npm 依赖，默认只监听本机回环地址。

若要同一局域网的手机和朋友加入，可运行 `HOST=0.0.0.0 npm run dev`，所有人打开运行服务的电脑的局域网地址（端口 `4173`）。四位 PIN 方便约房，不是公网安全边界；当前面向受信任的好友网络。

### 本地机器人测试

本地开发环境若已配置 `local-test/`，可运行 `node local-test/serve.mjs` 打开 [本地测试面板](http://127.0.0.1:4174/local-test/)。单人测试可先加一个机器人再开局，也可在局中添加。机器人从本局未使用的牌池抽牌，可通过面板跳过它的回合。测试评分独立保存在 `.state/local-test/`。

房间从五张本地原版场景中随机选择一张背景；同一房间的玩家、观战者和重连者共享背景，换局不重抽。首页仍使用水晶球背景。头像包含原版角色和奶龙 MOD（`sts_nndx/res/face`）提供的四张图片。卡面仍由图鉴使用的渲染器绘制。

- 支持按类型、卡框颜色、卡池、稀有度、基础能量费用组合筛选；可按名称、卡牌 ID 或词条搜索。
- 图鉴默认按稀有度筛选框的顺序排序，同一稀有度按中文名称排列。
- 颜色收在「更多筛选」中；诅咒和任务卡框归入「其他」，原始卡框和卡牌类型不变。
- 点卡面查看详情，切换基础版和升级版。「疯狂科学」可切换攻击、技能、能力变体。
- 卡面通过 `public/renderer.js` 在浏览器里拼合原版素材，不需要为每张牌预生成完整大图，也不需要运行游戏。浏览器排版、图标与动态效果不保证和游戏逐像素一致。
- 描述使用游戏原版的角色能量与辉星小图标。图鉴按 1–3 个并排、4 个及以上用数字加单个图标显示。

## 数据与素材

| 路径 | 用途 |
| --- | --- |
| `cards.sqlite` | 本地 SQLite，可用 `sqlite3` 查询。 |
| `.state/card-scores.sqlite` | 本地默认的用户评分库，独立于导入产物，不随发布覆盖。 |
| `public/data/cards.json` | 图鉴使用的快照：卡牌、版本、翻译、渲染参数和素材映射。 |
| `public/data/community-scores.json` | 按卡牌 ID 的同版本社区抓牌快照，只保存汇总，不保存玩家对局。 |
| `public/assets/art/` | 插画单层，含可用的测试版插画。唯一使用原版占位图的是 `DEPRECATED_CARD`。 |
| `public/assets/ui/` | 外框、按类型变化的插画边框、标题带、费用图标等共用图层。 |
| `public/assets/card-font.otf`、`card-font-subset.otf` | 完整字体和网页使用的卡面字形子集。 |

以卡牌 ID 作为主键；同名的各角色「打击」不会合并。卡池和卡框颜色单独保存，因为有少数事件牌会借用角色卡框。能量和星星费用以数值、`"X"` 和 `null` 分别表示固定费、X 费和不显示费用，`0` 不是空值。记录含简中、繁中、英文名称与描述模板、关键词、初始数值、升级变化和源码索引。预览按卡牌初始状态计算，不模拟战斗中的条件、变体词缀或永久成长。强度排名未接入社区榜，`rank` 保留为空。

### 评分数据与版本更新

- 评分库记录每张卡的稳定键和临时身份的哈希，分数由去重后的记录数计算。它不写入 `cards.sqlite` 或 `public/data/cards.json`；重新导入、替换发布目录或重启不会覆盖评分。
- 相同 ID 换名称、卡池、卡面或能力时保留评分；新增 ID 从 0 开始。下架卡的评分保留但不展示，同 ID 回归时恢复。不同角色的同名卡分别计分。
- 更新前核对新增、改名、下架的 ID。若同一张卡只是改了 ID，在 `scripts/card-score-aliases.json` 写入 `{"新ID":"旧稳定键"}`，沿用历史评分及去重记录；若旧 ID 改给一张不同的牌，给它分配从未使用的稳定键。不要依据同名自动合并或改写既有映射。启动时拒绝循环映射和两个在库卡共用一个稳定键。
- 部署时应给猜牌服务配置独立可写的持久目录：systemd 设置 `StateDirectory=sts2ciku` 和 `StateDirectoryMode=0700`，或设置 `STS2CIKU_STATE_DIR` 指向发布目录外的持久目录。部署、回滚只切换程序文件及匹配的别名表，不替换评分库。用 SQLite 的 `.backup` 定期备份，不在线只复制数据库主文件。

社区抓取率来自 [Spire Codex 的同版本导出](https://github.com/ptrlrd/spire-codex#tier-lists-exports-everything-else)。只统计单人、标准模式、无规则修饰器的六角色对局；排除商店，以及 5 个地图节点以内放弃的对局。抓取率是记录到的选中次数除以出现次数，合并同一卡牌的基础版与升级版。

评分先用整体抓取率加 50 个等效样本做平滑，再把有数据的最低和最高值线性映射到 1 和 100，最后取整。同值同分；无样本为 0，不参加拉伸。更换游戏版本后应重新导入对应归档，旧版快照不会显示。可运行 `curl -fSL 'https://spire-codex.com/exports/runs-v0.113.1.jsonl.gz' | node scripts/import-community-scores.mjs`；导入器只处理数据，不写玩家「考」的 SQLite。

```sql
SELECT id, name_zh, pool, rarity, energy
FROM cards
WHERE type = 'Attack' AND color = 'red'
ORDER BY name_zh;
```

## 重建

当前导入器针对已核对的版本和反编译结构。使用 Godot 4.5.1 从同版本 Steam 资源包解码素材；导入时可能会短暂出现 Godot 窗口。源目录和游戏资源包只读。

导入器使用 HarfBuzz 的 `hb-subset` 生成卡面字体子集，覆盖基础版、升级版和所有卡牌变体。未安装该工具时，网页使用完整字体。

```sh
npm run import
```

默认读取上一级的 `SlayTheSpire2`、macOS 上 Steam 安装的游戏资源包，以及 `/Applications/Godot_mono.app/Contents/MacOS/Godot`。位置不同时可显式传参：

```sh
npm run import -- <反编译源码目录> "<游戏资源包.pck>" "<Godot 可执行文件>"
```

资源包旁须有游戏的 `release_info.json`。重建会检查版本和提交号，生成 SQLite、卡牌 JSON 和卡面图层。房间背景和头像需另行准备，文件名见 `public/room-backgrounds.js` 和 `public/avatars.js`。社区评分可在生成卡牌数据后用 `scripts/import-community-scores.mjs` 汇总。
